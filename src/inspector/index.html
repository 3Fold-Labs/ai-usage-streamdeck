Connection settings

Uses the active Grok Bot Desktop sign-in to read its included weekly subscription allowance. Keep Grok Bot signed in so it can renew its session. This is the Bot allowance, separate from regular Grok / SuperGrok usage.

The sign-in token is read locally and sent only to Grok Bot’s existing backend at api2.cursor.sh. On Mac, macOS may ask you to allow access to the Grok Bot Keychain item. If access is denied, automatic retries pause until you select Refresh now. No API key, chats, extra credits, or billing changes are used.

Reads Cursor’s own sign-in from its local state database (User/globalStorage/state.vscdb), opened read-only, to show included plan usage for the current billing cycle. Keep Cursor signed in so it can renew its session.

The sign-in token is read locally and sent only to Cursor’s dashboard service at api2.cursor.sh. It is never saved in settings or logs. No refresh token, API key, chats, or billing changes are used.

Reads the Grok CLI sign-in from ~/.grok/auth.json to show the SuperGrok subscription’s shared weekly usage pool. Chat, Imagine, Voice, Build and the CLI all draw from this pool, as shown in grok.com Settings → Usage. It is separate from the Grok Bot allowance and from API billing.

The session key is read locally and sent only to the Grok CLI’s service at cli-chat-proxy.grok.com. It is never saved in settings or logs. The refresh token is never read, and no API key, chats, or billing changes are used. CLI sessions last about six hours and only the Grok CLI renews them. When the session expires, the key keeps its last reading with an amber dot until you run grok again.

Uses your existing Codex sign-in with ChatGPT. These are Codex subscription limits, not general ChatGPT message limits. No API key is needed.

Automatically reads Claude Desktop’s local subscription usage history. Keep Claude open; if the reading becomes stale, open Settings → Usage in Claude. History does not include reset times.
